# slicer-profiles scaffold (bare)
Generated by `nix flake init -t github:cpederkoff/slicer-profiles-nix#bare` - an empty scaffold meant to be filled by `import-profiles`, copied into an existing Home Manager config (e.g. `home/slicer-profiles/`), not used as a standalone flake

This variant ships no example profiles - just empty `printers/`, `filaments/`, and `prints/` directories (each with a `_common.nix` stub). Run `import-profiles` to populate them from your existing slicer profiles; see the main repo's [README](https://github.com/cpederkoff/slicer-profiles-nix) Quick start. Want a working example profile to hand-author from instead? Use the default template (`nix flake init -t github:cpederkoff/slicer-profiles-nix`).

## How to run
### Wire it in
The flake must be in scope of this module. The simplest way is to reference `inputs` (threaded in via Home Manager's `extraSpecialArgs = { inherit inputs; }`, or `specialArgs` under a NixOS `home-manager.users.*`):
```nix
{ lib, inputs, ... }:
let
  slicer-profiles-nix = inputs.slicer-profiles-nix;
  slicerLib = slicer-profiles-nix.lib.mkProfileLib { inherit lib; };
in
{
  imports = [ slicer-profiles-nix.homeModules.default ];
  slicerProfiles = import ./slicer-profiles/profiles.nix { inherit lib slicerLib; };
}
```

### Add your own profiles
Every `*.nix` file dropped in `printers/`, `filaments/`, or `prints/` becomes a profile automatically (`profiles.nix` scans them, so there's no list to maintain) - `import-profiles` writes them for you, or drop your own alongside.
